# CONTEXT — доменный словарь проекта «Building Automation»

Термины домена. Архитектурная лексика (module, interface, depth, seam, adapter) —
в скилле `improve-codebase-architecture`, здесь не дублируется.

Полное описание требований — [`docs/requirements/TZ.md`](docs/requirements/TZ.md), постановка —
[`docs/requirements/task.md`](docs/requirements/task.md).

## Уровни объекта

| Термин | Что это в Home Assistant | Кто управляет |
|---|---|---|
| **Объект** | — | наследование профилей |
| **Этаж** | Floor + агрегатная Area | Оркестратор |
| **Помещение** | Area | Оркестратор |
| **Зона** | — (группа `light.<room>_<n>`) | `zone_manager`, вне периметра |
| **Светильник** | `light.l_*` | DALI-интеграция, вне периметра |

Периметр Оркестратора — от объекта до **помещения** включительно.

## Состояние

- **Режим управления** — `Авто` либо `Ручной`. Задаётся для здания и для этажа;
  режим здания абсолютен, этаж может только ужесточить.
- **Режим расписания** — `Урок` / `Перемена` / `Не рабочее время` / `Окошко`.
  Вычисляется всегда, в том числе в Ручном режиме.
- **Применённый режим** — режим, действия которого фактически выполнены. Может
  отставать от режима расписания на время задержки.
- **Fallback-режим** — режим, в который система уходит при пустом или
  недоступном расписании.

## Настройки режима

- **Задержка перехода** — одна на режим, на всё здание. Отсюда: одновременно
  существует не более одного **отложенного перехода**.
- **Флаг «датчики разрешены»** — свойство режима, переопределяемое на этаже.
- **Профиль** — список действий для помещения при наступлении режима.
  Наследуется Объект → Этаж → Помещение, назначается также по метке типа.

## Ключевые понятия

- **Гейт** — сущность `binary_sensor` на этаж, разрешающая работу автоматизаций
  по датчикам. Условие в blueprint — `condition: template` вида
  `{{ states(<гейт>) != 'off' }}` (**fail-open**: отсутствие, `unavailable` и
  `unknown` разрешают работу). `condition: state` для этого непригоден — на
  несуществующей сущности он бросает ошибку и даёт fail-closed.
- **Каскад** — применение действий текущего режима ко всем помещениям.
- **Схлопывание** — выбор самого высокого уровня групп, на котором результат
  каскада однороден. Однородность определяется совпадением **списка действий**.
- **Инвариант Area** — в Area ровно одна сущность домена `light` (групповой
  светильник уровня). Нарушение → каскад по этой Area не выполняется.
- **opt-out** — метка на Area, исключающая помещение из управления расписанием.
- **Осиротевший профиль** — профиль, чей `area_id` или `floor_id` исчез из
  реестра.
- **Аномалия источника** — одновременно активны несколько типов событий
  расписания; разрешается приоритетом `break > window > lesson > off`.

## Внешние системы

- **`ha-lighting-compilers`** — генератор конфигов из Excel. Владеет Floors,
  Areas, групповыми светильниками, метками, скриптами, автоматизациями и
  blueprint'ами. Контракт доработок —
  [`docs/contracts/contract-ha-lighting-compilers.md`](docs/contracts/contract-ha-lighting-compilers.md).
- **`zone_manager`** — управление по датчикам движения. Оркестратор не знает о
  нём: влияет только публикацией гейта.
- **`event_schedule`** — источник расписания: набор сущностей со `state == "on"`
  и атрибутом `event_type`.
